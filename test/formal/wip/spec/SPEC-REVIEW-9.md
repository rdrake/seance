## Findings

1. **Liveness mode does not guarantee absence of VIEW or symmetry.** It disables *adding* SafetyView, but copies any existing VIEW/SYMMETRY unchanged; `--liveness --symmetry` explicitly adds symmetry. Thus D26's “no VIEW and no symmetry” claim is conditional on the input and options, not enforced. A safety projection can merge liveness-distinct states; symmetry is also unsuitable for TLC liveness checking. Reject these combinations/directives in liveness mode. (`hpc/split-env.py:28-29`, `hpc/split-env.py:36-38`, `hpc/split-env.py:42-59`; `DECISIONS.md:166-168`; `model/SpecHandshake.tla:681-685`.)

With `--two-other`, 96 slices cover the eight subsets for exactly the two quoted strings `"a"`, `"b"`. The script never derives these values from the config. Different cap names, additional caps, or model values used for symmetry can leave initial states uncovered or produce empty slices. Validate the universe or derive it from the config. Pinning `srv.offered` **only in SliceInit** is correct: EnvChange must remain free to change it later. (`hpc/split-env.py:37-42`, `hpc/split-env.py:62-79`; `model/SpecHandshake.tla:68`, `model/SpecHandshake.tla:102-109`, `model/SpecHandshake.tla:373-390`.)

Rule907 covers the authenticated case only; OwedSent does not count abort replies as owed. W_AbortChal records sending `*`, not the server consuming it or replying.
