## 2. New code

- **HandleAll and note batches: correct within scope.** The recursion feeds each result into the next line, preserving wire order and first-settlement absorption (`model/Delivery.tla:160-180`). NOTE is informational (`../formal-spec/specs-src/extensions/standard-replies.md:19`); ignoring it while continuing to echo/FAIL is appropriate. The new batches exercise scanning past a nonsettling prefix, not first-settling-line-wins between competing outcomes.
- **FAIL inheritance: correct.** `Handle` computes the effective label once and uses it for FAIL as for echo (`model/Delivery.tla:169-175`). `failB` and `noteFB` supply unlabeled inner FAILs (`:107-114`), consistent with the labeled logical response (`../formal-spec/specs-src/extensions/labeled-response.md:53-58`). This is not evidence of a newly repaired v0 FAIL bug: Review 1 already found inheritance correct for reachable lines (`MODEL-REVIEW-1.md:7`). v1 adds coverage here.
- **Self-copy: correct restricted construction.** Success to self adds an unlabeled delivered copy outside the response batch; failures add none (`model/Delivery.tla:101-116`). This respects LR's distinction (`../formal-spec/specs-src/extensions/labeled-response.md:60,87-92`). It fixes the ordering to echo-before-delivery and uses the same `k`/`who` for both; no role ghost establishes that distinction independently.
- **crossTimed: correct for its stated event.** It becomes sticky only on an actual pending-to-terminal settlement, with a distinct request as source whose outcome is then timedout (`model/Delivery.tla:160-166`). Reading `s.p` is correct during the fold; timeouts absorb. `NoCrossFromTimedOut` forbids that event, not merely receiving late traffic (`:255`). It is intentionally broader than “SLate echo,” but the witness switches isolate that source.
- **early: correct but narrow instrumentation.** In baseline Deferred, the member-buffering branch prevents the OTHER branch from processing an inner line; at end, the batch is closed in the resulting state (`model/Delivery.tla:194-205`). In DM_Early, removing buffering exposes exactly the guarded outcome change (`model/DM_Early.tla:198-204`). Thus baseline `~early` follows largely from control flow. It does not independently monitor every possible settlement while a batch is open, nor prohibit timeouts during an open batch—which the stated property correctly permits.

## 3. Mutants and witnesses

- **DM_FirstOnly:** exactly the named behavioral change (`model/DM_FirstOnly.tla:196`). A note-first response leaves its request pending forever with timeout/fallback off, violating ResolvedByResponse for the intended reason (`model/BaseDeferredNoTimeout.cfg:7-12,22`). Self-delivery cannot rescue it because fallback is off.
- **DS_InnerLabel:** exactly labels the simple batch's inner echo; noteB is untouched (`model/DS_InnerLabel.tla:103,111-114`). The start plus inner label increments the send count by two immediately, so LabelOnce fails before client handling (`:89,122,238`). This is the intended negative control.
- **DS_Twice:** the sole edit retains `owed` (`model/DS_Twice.tla:119`). This permits arbitrarily many answers, not exactly two. Under Base each answer adds one labeled send, so the second violates LabelOnce as intended (`:116-122`). The shortest counterexample may queue both answers before either is consumed; it proves duplicate sending, not specifically sending again after completion or timeout. Continuing this mutant without stopping at the violation also gives unbounded wire/reference/count growth.
- **W_SelfCopy isolates the delivered-copy source, but not the full D15 chronology.** With Lossy and OtherSession off, only a self-delivered unlabeled line can cross-confirm another request; target matching requires both requests to be self-targeted (`model/W_SelfCopy.cfg:7-12`; `model/Delivery.tla:101-116,150-175`). However: send identical A/B, timeout A, consume A's ignored labeled echo, then consume A's delivered copy to confirm B. This violates ConfirmedByOwn without “the labeled echo settles A” (`DECISIONS.md:284-286`). The README's narrower source claim is sound (`model/README.md:71-72`); the full causal story needs a role ghost and a condition that A was confirmed by its labeled echo before its delivered copy settles B.
- **W_LateTimedOut does isolate its advertised story.** SelfMsg and OtherSession are off; ordinary batch members inherit their own label, so only SLate's unlabeled echo can settle a different copy. The ghost additionally requires source A already timedout and recipient B still pending (`model/W_LateTimedOut.cfg:7-15`; `model/Delivery.tla:131-134,160-175`). Unlike W_LateFallback, no no-timeout cross-match can violate this invariant. It does not require B to be sent after A timed out, nor A's echo to be generated after timeout; neither is promised by the stated witness. CoverCrossTimed checks the same event's reachability, not independent evidence (`:255,273`; `model/CoverCrossTimed.cfg:14`).

## 4. Before History

**The README's “Still open” list is not complete.** Besides its listed gaps, retain: incomplete TypeOK and provenance stability/ownership checks; ACK consumption specifically; separate FAIL/4xx dispatch coverage; explicit after-completion/timeout duplicate-send scenarios; and the stronger self-copy chronology above (`model/Delivery.tla:231-258`; `MODEL-REVIEW-1.md:5,16-18`). Bounds mismatch is acknowledged elsewhere, not settled (`model/README.md:16-17`). “No unlabeled echo possible” also needs “no standalone/effectively unlabeled echo”: batched echoes are literally unlabeled (`model/README.md:44`; `model/Delivery.tla:103`).

Before History shares this machinery, replace the single slot with reference-indexed batch state, separate own batch identifiers from parent membership, and exercise interleaving plus depth-two nesting. BA explicitly permits these (`../formal-spec/specs-src/extensions/batch.md:51-63,100-123`); DESIGN explicitly makes them the joint (`DESIGN.md:16-18,53`). Add competing settling lines in both orders, direct immediate/deferred consumption obligations, and timeout/close races with defined buffered-reply handling. Reconcile bounds and add targeted covers/negative controls before accepting passes as evidence. Define a typed History-response interface so replayed PRIVMSGs do not automatically become outgoing-message confirmations. Keep History separate as DESIGN requires (`DESIGN.md:6-18`), and validate the claimed Seance policy through replay before calling these code findings (`DESIGN.md:187-192`; `model/README.md:74-77`).
