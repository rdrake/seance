# Delivery.tla (model v2.1) and its checks

`Delivery.tla` models the delivery of the client's own messages: labeled-response, echo-message
and batch, with Seance's pending copies (D15). It is built from `../DECISIONS.md` (D1, D2, D12,
D13, D15-D21) and checks the properties in `../DESIGN.md`. v2 answers `../MODEL-REVIEW-2.md`;
v2.1 adds the fixes from DECISIONS-REVIEW-6. Earlier versions: `.Delivery-v0.tla.ref`,
`.Delivery-v1.tla.ref`, and the v1 README `.README-v1.md.ref`.

**What v2 changed:**
- **Queued responses (D16).** Responses are queued per label and emitted one line at a time, so
  two responses can interleave on the wire. The client keeps a map of open batches keyed by
  reference (`ob`): each entry holds its own label, its root, and whether it is a history batch.
- **Depth-two nesting (D16, D19).** A labeled batch may hold one inner batch: a multiline echo,
  or a history replay. Under `Deferred`, lines are buffered per root batch (`buf`) and handled
  in order at the root's end.
- **Switches.**
  - `Competing` (D17): one response holds both an echo and a FAIL.
  - `CloseOn` (D18): the connection may close, and every pending copy is then failed.
  - `History` (D19): same-text replays come in three forms: plain, nested in a labeled batch,
    and direct. A recognised history line never settles a copy.
  - `Notice` and `Modify` (D20): NOTICE requests, and server-altered echo texts.
  - `MaxLate` (D20) bounds the late unlabeled replies.
- **Ghosts:** `firstK`, `role`, `crossDeliv`, `histSettled`, `kindCross` and `modConf`, for the
  new witnesses and invariants.
- **Consumption obligations (D21).** These are action properties.
  - `ImmediateObligation`: a settling line consumed outside a deferred batch, for a copy that is
    still pending, settles that copy with `Expect(kind)`.
  - `DeferredObligation`: at a root batch's end, the first eligible buffered line for each
    pending label settles it with `Expect(kind)`.
- **Mutants:** generated by `mkmut.py`. Rerun it after any change to `Delivery.tla`.

**Bounds:**
- 2 labels, never recycled;
- 2 texts;
- MaxReq requests (2 in most configs, 1 in V2HistoryDeferred);
- MaxLate = 2;
- depth two;
- one other-session line and one history replay.

## What the witnesses say about Seance's stated policy

With the content fallback on, the policy (`settleEcho`) can confirm a pending copy on a line
that answers something else, in three ways:
- a same-text line from another session of the same account (W_Other);
- the late unlabeled echo of another copy, including one that has already timed out
  (W_LateFallback, W_LateTimedOut);
- the unlabeled delivered copy of a message to one's own nick, settling a second identical
  self-message (W_SelfCopy). This one needs neither Lossy nor another session.

With the fallback off, ConfirmedByOwn holds in every positive config. These are properties of
the stated policy, found by the model. None is yet confirmed against Seance's code by a replay
harness. What the user then sees (for example a duplicate line) is outside the model, which
has no display buffer.
