**Verdict: useful restricted v0, but insufficient evidence of D15 fidelity or mutation adequacy.** The response choices are substantially right; important client behavior is unreachable, and the advertised late-timeout witness is underspecified. Static review only: I did not run TLC or confirm the cluster results in `model/README.md:21`.

## 1. Fidelity

- **Server choices match the narrowed D1/D15 table.** `Full` contains a labeled echo or failure, standalone or batched; ACK-only, empty partial batch and silence are confined to `Lossy` (`model/Delivery.tla:84-102`; `DECISIONS.md:64-73`, `DECISIONS.md:270-279`). The separate late branch produces an unlabeled echo. This correctly keeps ACK-only out of conforming PRIVMSG success under echo-message (`../formal-spec/specs-src/extensions/echo-message.md:21-24`). The action's introductory comment still calls ACK conforming (`model/Delivery.tla:76-80`), contradicting its actual choices. `fail` abstracts both FAIL and 4xx; it does not exercise their separate dispatch paths.
- **Freshness and absorption are correctly implemented within scope.** `CSend` allocates unused labels; `Settle` only changes pending entries; `CTimeout` records a terminal timeout (`model/Delivery.tla:66-74`, `model/Delivery.tla:130-133`, `model/Delivery.tla:177-180`). Fairness implements eventual processing/answer/timeout, not a measured 60 seconds (`model/Delivery.tla:190-192`; `DECISIONS.md:230-244`). `SLate` also has explicit weak fairness, an additional restriction on the chosen late-response branch. `SOther` is the allowed once-only same-text environment line, not the LR-5 self-delivery case (`model/Delivery.tla:113-118`).
- **Handle is faithful for reachable lines.** It inherits a batch label, gives labeled echoes priority over fallback, uses the oldest pending exact-text copy for an unlabeled echo, and maps echo/ACK/fail to confirmed/accepted/failed (`model/Delivery.tla:125-146`). Same kind and channel are implicit because every request is a PRIVMSG to one channel. A terminal labeled response cannot fall through and settle a different copy. First-settling-line-wins follows from `Settle`, but no generated batch contains two settling lines.
- **Deferred processing is only accidentally complete.** At closure `CRecv` handles `open.lines[1]` and discards every later line (`model/Delivery.tla:156-164`). This works for the generated batches, which have zero or one inner line (`model/Delivery.tla:85-88`), but does not implement D15 for a batch with a nonsettling line followed by an echo or FAIL. BA permits delaying *events*, not dropping all but the first (`../formal-spec/specs-src/extensions/batch.md:55-58`). Add ordered processing of all buffered lines before claiming general deferred fidelity; test both echo-then-fail and fail-then-echo.
- **Batch association is assumed rather than checked.** One `open` slot is overwritten on every start; inner lines inherit its label without comparing references, and any end clears it (`model/Delivery.tla:153-169`). Atomic append of complete responses makes these shortcuts safe here (`model/Delivery.tla:97`). They are narrower than legal interleaving (`../formal-spec/specs-src/extensions/batch.md:100-110`). The `ref` on start/end records must also be understood as the batch's own identifier, not a literal wire `batch=` tag: BA forbids self-membership (`../formal-spec/specs-src/extensions/batch.md:51-52`).

## 2. Properties

- `LabelOnce` states the whole-run upper bound correctly, but cannot fail in this model: only `SAnswer` increments the counter and it permanently removes the label from `owed`; `SLate` never labels (`model/Delivery.tla:94-110`, `model/Delivery.tla:203`). No supplied server mutant challenges it, despite D2 explicitly requiring that test (`DECISIONS.md:92-93`).
- `PendingResolves` correctly states eventual departure from pending, with uniqueness/stability supplied separately by the scalar outcome and `Absorbing` (`model/Delivery.tla:220-223`). With `TimeoutOn`, a label that stays pending keeps its timeout continuously enabled, so weak fairness alone forces resolution. It tests little response handling; it is not literally vacuous, but timeout-dominated. No request is required to be sent either; covers establish existence of interesting executions, not universal sending.
- `ResolvedByResponse` excludes timeout and is useful under `NoTimeout.cfg:7-19`; its formula also permits accepted, although DESIGN describes confirmed or failed (`model/Delivery.tla:225-227`; `DESIGN.md:145-146`). Accepted is unreachable in that config, so this discrepancy does not affect the present check.
- **The two response properties are insufficient across the suite.** `OutcomeMatchesCause` checks only terminal outcome implies recorded kind; it never requires an eligible received line to settle a pending copy (`model/Delivery.tla:209-214`). A client that ignores ACK passes all current positive checks: ACK is reachable only under Lossy, where timeout resolves the copy. A client that ignores every deferred inner line also passes the deferred config through timeout (`model/BaseDeferred.cfg:8-24`); the only response-liveness config has Deferred off (`model/NoTimeout.cfg:8`). `ResolvedByResponse` plus `OutcomeMatchesCause` does catch ignoring or misclassifying the sole conforming response in the timeout-free immediate configuration, provided cause instrumentation remains truthful. Add transition obligations for eligible response consumption, including buffered processing, and timeout-free deferred checks.
- `ConfirmedByOwn` correctly distinguishes cross-copy confirmation using provenance rather than equal text (`model/Delivery.tla:139-145`, `model/Delivery.tla:206`). It says nothing about ownership of failed/accepted outcomes; those branches hard-code `by = "own"`. `cause` records the actual consumed kind, but neither ghost is an independent full response log.
- `DeferredWaits` correctly checks the instrumented early-settlement event under Deferred, not eventual processing (`model/Delivery.tla:172`, `model/Delivery.tla:217`). `Absorbing` correctly preserves terminal outcomes, but not their provenance ghosts (`model/Delivery.tla:220`). `TypeOK` is a small sanity check, not a full type invariant: it omits wire, batch, function-domain and ghost-shape checks (`model/Delivery.tla:198-200`). The five covers assert the negations of their named reachability goals correctly (`model/Delivery.tla:229-234`), but do not cover two settling lines, multiple open batches or the claimed late-after-timeout causal chain.

## 3. Mutants and witnesses

Each mutant differs only by its module name and the advertised behavioral edit:

| Mutant | Static assessment |
| --- | --- |
| `DM_IgnoreEcho.tla:140` | Ignores echoes with an effective label, including inherited labels. Matches README; NoTimeout can expose permanent pending after an echo. |
| `DM_WrongLabel.tla:140` | Settles oldest same-text pending copy instead of the labeled copy and records the true originating request. Two identical outstanding requests answered in reverse order expose it. |
| `DM_Early.tla:165` | Disables buffering, so inner lines are handled immediately and `early` detects settlement. Matches README. |
| `DM_Flip.tla:131` | Removes the pending guard for all settlements. Timeout followed by a labeled response changes a terminal outcome, exposing Absorbing. Fallback still selects only pending copies through Oldest. |

The README's mutant failures are plausible by inspection, not independently confirmed (`model/README.md:34-37`).

- **W_Other:** the only foreign source is `SOther`, so a ConfirmedByOwn failure identifies the stated same-text other-session confusion (`model/W_Other.cfg:7-14`; `model/Delivery.tla:114-118`).
- **W_LossyNoTimeout:** silence can remove an owed response without producing a line; with timeout disabled, permanent pending is possible even with fairness (`model/W_LossyNoTimeout.cfg:7-15`; `model/Delivery.tla:93-102`). An empty partial batch also suffices. The config permits the claimed story but does not isolate total silence from other nonsettling responses.
- **W_LateFallback does not establish that A timed out.** Send B first and A second with identical text, choose the late branch for A, then receive A's unlabeled echo while both are pending. Oldest selects B; `by[B] = A` violates ConfirmedByOwn with no timeout at all (`model/W_LateFallback.cfg:1-14`; `model/Delivery.tla:107-110`, `model/Delivery.tla:125-143`). The intended A-timeout-then-B story is also reachable, but the check cannot distinguish it. `who`/`by` identify A; `cause[B]` says echo, not A's state when that echo arrived. Require a ghost event recording cross-settlement specifically while the source is timedout, and cover that event.
- The assertion that the wrongly settled copy's own echo later appears as an extra line is beyond the model (`model/README.md:46-47`): no incoming-display buffer or display events are represented, and the copy's own response could instead fail or disappear under Lossy.

## 4. Bounds, gaps and v1 priority

1. **First add two independently open, interleaved batches and multiple inner lines**, with a reference-indexed batch map and ordered deferred processing. This directly challenges label inheritance, association and first-settling-line-wins, where current implementation shortcuts are hidden. Pair it with timeout-free deferred liveness and response-consumption checks.
2. **Add a second-labeled-response server mutant**, including after timeout/completion, and a separately labeled inner-line mutant. Count actual labeled sends so both violate LabelOnce. This supplies the missing negative control for D2.
3. **Add the conforming self-message pair**, labeled echo plus unlabeled delivered copy, with two identical pending self-messages. This can break fallback ownership with Lossy and OtherSession both off (`DECISIONS.md:284-296`; `../formal-spec/specs-src/extensions/labeled-response.md:60`, `:87-92`). BaseFallback's success currently depends on excluding this case.
4. **Add connection close**, failing pending copies locally and defining what happens to queued/buffered replies; extend cause validation to local close (`DECISIONS.md:278`).
5. **Add NOTICE and kind-sensitive fallback**, since echo-message explicitly covers it (`../formal-spec/specs-src/extensions/echo-message.md:21-29`). Identical PRIVMSG/NOTICE text must not cross-settle; additional targets would similarly test channel matching. Also exercise server-modified echoes, which the spec requires clients to tolerate but v0 never generates (`model/Delivery.tla:82-89`; `DECISIONS.md:277`).

Finally, align the scope documents: DESIGN promises up to three requests, depth two, at most one late reply and a self-message (`DESIGN.md:51-55`); v0 has two requests, depth one, no self-message, and can place both labels in `late` (`model/README.md:7-16`; `model/Delivery.tla:101`). These are material differences in coverage, not confirmed spec or Seance defects.
