## Possible bugs

None beyond the two known ones. Side notes, not bugs:

- `aliases.ts:218`: the body of the `--budget.left < 0` guard is unreachable, because L242 always stops first.
- `token.ts:21/38`: the `""`/`*` service guards duplicate the per-service match in `authtoken.take`.

## Weak tests

1. `test/irc/catchup.ts` › "goes in JOIN order when the server refuses, and does not ask that server again": the "FAIL is not shown" check compares `socket.dispatch.callCount`, but the harness client dispatches to its own `h.dispatch` spy, so the check always holds (6524). The client takes `options.bus ?? socket` (`client.ts:505`). `catchup.ts:836/841` is the only place in `test/irc` that uses this idiom.
2. `test/irc/persistence.ts` › "holds the autojoin through an unbatched burst and its bouncer note": with this timing the original wait and the burst's JOINs hold the autojoin, so the note's re-arm is never exercised (6651).
3. `test/irc/handlers/privmsg.ts` › "does not read ##chan as a status prefix on #chan": `#` is not a STATUSMSG character, so the `!isChannelName` guard it is named for never decides the outcome (5920–5922).
4. `test/irc/handlers/privmsg.ts` › "CTCP replies (NOTICE) shows the reply and sends nothing back": it does not assert `showInActive` (true in the lobby) or the unread count (6170–6173).
5. `test/irc/saved-networks.ts` › "falls back to Math.random without any crypto": it checks only the format, and all-zero bytes pass. It needs a stubbed Math.random and the exact uuid (8251, 8252, 8254, 8256, 8257).
6. `test/irc/commands.ts` › "/me and /slap only works in channels and queries": the query half is never exercised (3407).
